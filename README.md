# Projects

Not a portfolio. A thinking process.

Real problems. Creative solutions. No filler.

## The Philosophy

I build things because there's friction to solve or something interesting to figure out. Not because it looks good on a resume.

**Real problem?** Does it solve something people actually encounter, or did I learn something that breaks how I think? If yes, it's worth building.

**Generic shit?** Hardpass. No CRUD tutorials dressed up as projects. No "learn React by building a todo app" nonsense. If it doesn't have a creative angle—a design decision that matters, a problem that forced me to think different—it doesn't go here.

**Both clean + working.** Architecture matters because messy code teaches you bad habits. Features working matter because non-working code is just theory. I refuse to sacrifice either.

## What's In Here

**Movie Ticket Website** — Seat selection UI, payment flow, theater management. Built to understand how real booking systems handle state and UX friction.

**HR Management System** — Employee records, profile management, authentication. Built with Java Servlets + JSP to understand how traditional server-side web works before jumping to frameworks.

Both projects have working features and clean structure. Neither is half-baked.

## The Stack

React, vanilla JS, HTML/CSS on frontend. Node, Spring Boot, Jakarta EE on backend—depends on what I'm drilling that cycle. Database design matters; I spend time on schema.

No "best practices" cargo cult. Tech choice is always: *Why does this fit the problem?*

## How I Work

I use Claude Code and Anthropic tools to handle boilerplate—scaffolding, repetitive config, basic structure. That frees me to focus on architecture, problem-solving, and the decisions that actually matter.

Not because writing it manually is beneath me, but because it's not where the thinking lives. My time is better spent on design tradeoffs, clean schemas, and solutions that scale.

This is how I approach real projects: leverage tools to focus on what only humans should be building.

## What You'll Find

- Code that works
- Decisions you can reason about
- Problems solved, not tutorials followed
- Room for improvement (that's kind of the point)
